Trabajo Práctico Nivelatorio
Backend de Gestión de Biblioteca

Introducción y Objetivo

El objetivo de este trabajo práctico es implementar el backend de una API REST completa enfocado en la gestión operativa de una Biblioteca, aplicando de manera estricta una arquitectura en capas fundamentada en la cadena de responsabilidades descrita como: Controller → Service → Repository.

Para el desarrollo del ecosistema se empleará la plataforma C# con .NET, integrando Dapper como micro-ORM ágil y optimizado para resolver la capa de persistencia y mapeo relacional. Asimismo, se exigirá la obligatoriedad de implementar DTOs (Data Transfer Objects) para aislar el modelo de dominio interno de los contratos de entrada y salida expuestos en la interfaz de comunicación HTTP. El control de los flujos de errores y excepciones de negocio deberá centralizarse a través del componente nativo de infraestructura IExceptionHandler de .NET.

Diagrama de Entidad-Relación (DER)

La persistencia subyacente de la aplicación se compone de tres entidades fundamentales normalizadas para asegurar la integridad de datos y el flujo de stock:

DDL Sugerido (SQL Server)

CREATE TABLE Libros (
    Id INT NOT NULL PRIMARY KEY IDENTITY(1,1),
    Titulo VARCHAR(200) NOT NULL,
    Autor VARCHAR(100) NOT NULL,
    ISBN VARCHAR(20) NOT NULL UNIQUE,
    CantidadDisponible INT NOT NULL DEFAULT 0
);

CREATE TABLE Socios (
    Id INT NOT NULL PRIMARY KEY IDENTITY(1,1),
    NombreCompleto VARCHAR(150) NOT NULL,
    Email VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE Prestamos (
    Id INT NOT NULL PRIMARY KEY IDENTITY(1,1),
    SocioId INT NOT NULL FOREIGN KEY REFERENCES Socios(Id),
    LibroId INT NOT NULL FOREIGN KEY REFERENCES Libros(Id),
    FechaPrestamo DATETIME NOT NULL DEFAULT GETDATE(),
    FechaDevolucion DATETIME NULL
);

Manejo Global de Excepciones (Middleware / Filter)

Cláusula de Control Estricta: Se penalizará explícitamente el uso de bloques tradicionales de captura imperativa de excepciones (try-catch) embebidos dentro de las acciones o métodos de los controladores.

Toda desviación operativa o regla de negocio insatisfecha en la capa de lógica interna deberá interrumpir de forma inmediata el flujo procedimental mediante el lanzamiento controlado de excepciones personalizadas fuertemente tipadas (por ejemplo: StockInsuficienteException, EntidadNoEncontradaException).

El motor de infraestructura capturará las anomalías de manera agnóstica utilizando un pipeline centralizado basado en la interfaz contractual IExceptionHandler de .NET Core. Este componente automatizará el mapeo directo de las excepciones hacia los códigos de estado estandarizados HTTP (400 Bad Request, 404 Not Found, 409 Conflict) envolviendo la respuesta final bajo el formato semántico normativo ProblemDetails (RFC 7807).
